# Views without a front end

The operator asks for occupancy, rate proposals and approval history. The CLI reads the database and writes printable reports using brand.json. One field or rule change can be made and tested in the same place as the records.

A conventional screen gives a visual rate calendar, drag-and-drop changes, mobile access and instant channel updates. This base supplies none of those. It does not serve a public booking page, collect payments, scrape competitors, supply market data or synchronise a channel. Its useful job is the internal rate review and its evidence.

A booking system connection, richer fee calculations or an operator screen is a scoped implementation job. Keep current booking distribution running until that work is built and checked. The local HTML reports are read-only files, not an access-controlled website. Keep them private.
